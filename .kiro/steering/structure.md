# Project Structure

## Root Directory

```
metricus/
├── metricus.sln              # Main solution file
├── GlobalAssemblyInfo.cs     # Centralized version info
├── README.md                 # Project documentation
├── LICENSE                   # Project license
├── SETUP-NOTES.md           # Environment setup notes
├── CONFIG-MANAGEMENT.md     # Configuration guide
└── FIX_CONFIGS.sh           # Configuration fix script
```

## Core Projects

### metricus/
Main service executable that hosts the plugin pipeline.

**Key files:**
- `Program.cs`: Entry point, TopShelf service configuration
- `Metricus/PluginLoader.cs`: Dynamic plugin loading
- `config.json`: Service configuration (interval, active plugins)
- `NLog.config`: Logging configuration
- `app.config`: .NET runtime configuration

### PluginInterface/
Shared library defining plugin contracts and core types.

**Key files:**
- `IInputPlugin.cs`: Input plugin interface
- `IOutputPlugin.cs`: Output plugin interface
- `IFilterPlugin.cs`: Filter plugin interface
- `metric.cs`: Core metric data structure
- `Plugin.cs`, `InputPlugin.cs`, `OutputPlugin.cs`, `FilterPlugin.cs`: Base classes
- `PluginManager.cs`: Plugin lifecycle management

## Plugin Projects

All plugins follow the same structure pattern:

### plugins/ConsoleOut/
Debug output plugin for development.
- `ConsoleOut.cs`: Implementation
- `config.json`: Plugin configuration (usually empty)

### plugins/GraphiteOut/
Graphite metrics output via TCP.
- `GraphiteOut.cs`: Implementation
- `config.json`: Graphite server, port, prefix, protocol settings

### plugins/PerfCounter/
Windows Performance Counter collection.
- `PerformanceCounter.cs`: Implementation
- `config.json`: Counter definitions (categories, instances)
- `README.md`: Plugin documentation

### plugins/SitesFilter/
IIS site-based metric routing.
- `SitesFilter.cs`: Implementation
- `config.json`: Category filters and routing rules
- `README.md`: Plugin documentation

## Scripts Directory

### scripts/
Build, deployment, and testing automation.

**Build & Deployment:**
- `Publish-Metricus-Zip.ps1`: Main build and packaging script
- `Update-Configs.ps1`: Configuration management
- `Restore-Packages.ps1`: NuGet package restoration

**Testing:**
- `Setup-TestIIS.ps1`: Create IIS test sites
- `Setup-TestIIS-WinPS.ps1`: Windows PowerShell version
- `Cleanup-TestIIS.ps1`: Remove test sites
- `Generate-Load.ps1`: HTTP load generation
- `Run-MetricusLoadTest.ps1`: Automated load testing

**Configuration Files:**
- `config-main.json`: Base service configuration
- `config-graphiteout.json`: Graphite output defaults
- `config-perfcounter.json`: Performance counter definitions
- `config-perfcounter-minimal.json`: Minimal counter set
- `config-sitesfilter.json`: Site filter rules
- `config-consoleout.json`: Console output settings
- `environment-overrides.json`: Environment-specific overrides

## Tests Directory

### tests/
Testing infrastructure and documentation.

**Scripts:**
- `Setup-IISTestSites.ps1`: IIS test environment
- `Generate-TestTraffic.ps1`: Traffic generation
- `Cleanup-IISTestSites.ps1`: Test cleanup
- `Test-GraphiteConnection.ps1`: Connectivity testing
- `send-test-metrics.ps1`: Manual metric sending

**Docker:**
- `docker-compose.yml`: Graphite + Grafana stack
- `grafana.ini`: Grafana configuration
- `grafana/`: Dashboard and datasource provisioning

**Documentation:**
- `README.md`: Testing overview
- `IIS-Testing-README.md`: IIS testing guide
- `LOAD-TESTING-GUIDE.md`: Load testing procedures
- `DASHBOARD-ACCESS.md`: Grafana access info
- `VM-CONNECTIVITY-FIXES.md`: Network troubleshooting

## Documentation

### doc/
Release and deployment documentation.
- `doc/release/chef/`: Chef deployment configs
- `doc/release/xwing/`: Xwing deployment configs

## Build Artifacts

### bin/ and obj/
Generated by build process (gitignored).
- `bin/Debug/`: Debug build output
- `bin/Release/`: Release build output
- `obj/`: Intermediate build files

### Plugins Output
All plugins build to the main service bin directory:
- `metricus/bin/{Configuration}/Plugins/{PluginName}/`

## Configuration Conventions

### Plugin Configuration Pattern
Each plugin has a `config.json` in its directory:
```
Plugins/{PluginName}/
├── {PluginName}.dll
└── config.json
```

### Environment-Specific Overrides
Base configurations in `scripts/config-*.json` are merged with environment overrides from `scripts/environment-overrides.json` during build.

## Naming Conventions

- **Projects**: PascalCase (e.g., `PerformanceCounter`, `GraphiteOut`)
- **Namespaces**: `Metricus.Plugin` for all plugins
- **Interfaces**: `I{PluginType}Plugin` (e.g., `IInputPlugin`)
- **Config files**: `config.json` (lowercase)
- **Scripts**: PascalCase with hyphens (e.g., `Setup-TestIIS.ps1`)
